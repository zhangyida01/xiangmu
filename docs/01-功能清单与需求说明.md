# 项目交付管理后台 · 功能清单与需求说明

> 版本：v0.3（阶段一代码已完成，功能范围与技术选型已确认）
> 部署环境：CentOS 7.9 宿主机 + Docker Compose
> 技术栈：Java 17 + Spring Boot 3 + MyBatis-Plus + MySQL 8 + Vue 3 + Element Plus
> 适用场景：个人 / 极小团队使用，单机部署
> 说明：v0.1 为需求梳理稿，v0.2 依据确认结果收敛范围，v0.3 同步阶段一实现状态，决策详情见第九章，交付物与实现状态见第十章。

## 一、项目概述

### 1.1 背景与痛点

项目交付过程中，交付资料散落在个人电脑、聊天记录、共享网盘和 Excel 表格里，常见痛点：

- 项目基础信息（合同、里程碑、环境、负责人）没有统一台账，交接靠人问人。
- 交付文档版本混乱，验收时找不到最终版；文档是否齐全没人说得清。
- 平台账号密码用 Excel 明文记录、微信/邮件传递，泄露风险高，事后无法追溯谁看过。
- 证书、域名、License、密码到期无人提醒，导致生产事故。
- 时间一长，自己也想不起来某个项目的服务器、后台地址和账号在哪。

### 1.2 系统目标

建设一套 B/S 架构的内部项目交付管理后台，实现：

1. 项目台账统一：一个项目一个主页，基础信息、进度、环境、文档、凭据、动态一屏看全。
2. 交付文档可控：分类归档、版本管理、在线预览、水印、缺项提醒、验收后锁定。
3. 账号凭据保险箱：加密存储、默认掩码、按账号权限查看明文、一键复制、到期轮换提醒、访问全程审计。
4. 全过程留痕：所有敏感操作（尤其是"看了密码"）都有不可篡改的审计日志。
5. 到期不漏：里程碑、证书、域名、License、密码轮换在站内自动预警。

### 1.3 使用对象与规模

主要供本人记录与查询项目交付情况，单人使用为主，最多再开 1～2 个协作账号；数据量为项目数十到数百个、文档与凭据数千条，附件总量预计数十 GB。属于轻量级内部工具，架构上优先"简单、可维护、单机可跑、易备份"，不引入微服务、缓存集群与高可用。

## 二、角色与权限模型

### 2.1 角色（已简化）

| 角色 | 说明 | 权限 |
| --- | --- | --- |
| ADMIN 管理员 | 默认就你一个 | 全部功能：项目管理、文档、凭据明文与导出、用户管理、系统配置、审计日志 |
| USER 普通用户 | 可选，给协作同事 | 项目与文档增删改查，凭据明文可见（可单独关闭），不能管用户与系统配置 |
| VIEWER 只读 | 可选 | 只能查看项目与文档，凭据始终掩码，不能下载导出 |

### 2.2 权限模型（已简化）

- 角色直接放在用户表 role 字段（ADMIN / USER / VIEWER），不做可视化权限点配置，也不做部门数据范围。
- 少量敏感能力单独开关：凭据明文查看、凭据导出、附件下载、项目删除；默认只有 ADMIN 全开。
- 后端接口用注解声明所需角色或能力，前端按登录返回的权限集合控制菜单与按钮显隐。
- 不论权限高低，查看凭据明文、复制、下载、导出一律写审计日志。
- 后续若扩展到多人多部门，再升级为完整 RBAC；当前表结构预留扩展空间，不需迁移数据。

## 四、核心功能详细描述

### 4.1 项目主页（360° 视图）

进入任一项目后，顶部为项目名 + 状态标签 + 健康度 + 负责人 + 关键日期倒计时，下方按 Tab 组织：

- 概览：基础信息卡片、进度条（里程碑完成率）、临期提醒、文档完成率、凭据数量、最近动态时间轴。
- 基础信息：可编辑表单（客户、合同、相关人、日期、简介、标签）。
- 环境与资产：交付环境列表（生产 / 测试 / UAT）、服务器信息、部署产品与版本、License。
- 里程碑 / 任务：阶段计划与实际、任务清单、Checklist 完成率。
- 交付文档：分类树 + 文件列表，显示版本、密级、上传人、大小、下载次数，支持上传 / 预览 / 下载 / 升版。
- 账号凭据：该项目全部凭据，默认掩码，支持查看 / 复制 / 编辑 / 到期提醒。
- 风险与变更：风险、问题、变更记录。
- 操作日志：本项目相关的审计流水。

### 4.2 交付文档的"清单化"管理

不只是网盘，而是交付物清单：

1. 为每种项目类型配置《交付文档清单模板》，例如"标准实施项目"必须包含：需求确认书、方案设计、部署手册、操作手册、测试报告、账号清单、验收报告、培训签到表。
2. 新建项目时选择类型，自动生成清单，每项目一条"应交文档"记录。
3. 上传文档时关联到清单项，清单项状态变为"已提交"，可进一步标记"客户已确认"。
4. 项目主页与列表页显示文档完成率（M/N），缺项红色高亮。
5. 验收 / 归档时校验：必填文档缺失给出阻断提示（可配置为强制或仅提醒）。

### 4.3 账号凭据保险箱（重点设计）

存储与加密

- 密码、私钥、Token 等敏感字段不明文入库，采用 AES-256-GCM 加密后存 密文 + IV + tag（Base64）。
- 加密主密钥（Master Key）不写在代码与数据库里，放在宿主机独立文件（权限 600）并以只读方式挂载进容器；备份数据库时必须单独备份主密钥，且两者分开存放。
- 用户登录密码使用 BCrypt 单向哈希，与凭据加密体系分离。
- 主密钥一旦丢失，已加密的凭据不可恢复，因此必须做离线副本。

查看流程

1. 列表页所有敏感值显示为掩码，账号显示为部分遮挡形式（如 ad***@corp.com）。
2. 点击"眼睛"图标 → 后端校验账号角色与"凭据明文查看"能力 → 若系统参数开启了二次确认，则要求再输入一次登录密码。
3. 校验通过后返回明文，同时写入审计日志（谁、何时、哪个项目、哪条凭据、IP、UA、结果）。
4. 明文在前端仅驻留内存，页面切换或 N 秒后自动隐藏；复制后 N 秒清空剪贴板。
5. 无权限账号看不到明文入口；后续如启用审批流，可申请并获得限时查看权。

到期与轮换

- 每条凭据可设"密码有效期（天）"与"上次修改时间"，到期前 N 天进入首页"临期预警"。
- SSL 证书支持解析证书文件读取 notAfter 自动获取到期日；域名到期日手工维护。
- 到期看板：30 天内到期清单，按剩余天数排序。

导入导出

- 导入：下载 CSV/Excel 模板 → 填写 → 上传 → 校验（重复检测、必填、格式）→ 预览确认 → 入库加密。
- 导出：高危操作，导出文件为带口令的加密 zip，口令另行保存；导出行为全量审计。

### 4.4 审计日志

- 采用"业务操作 + 统一 AOP 切面"记录，避免遗漏；写日志失败不阻断业务但打印告警。
- 敏感值在日志中一律脱敏（只记录字段名与是否变化，不记录明文或密文值）。
- 日志表只允许 INSERT 与 SELECT；应用不提供修改 / 删除接口。
- 支持按"用户 + 时间 + 项目 + 动作"组合查询，导出 CSV。

### 5.1 文件存储约定

- 附件根目录：/data/pdm/uploads/{projectId}/{yyyy}/{MM}/{uuid}.{ext}，数据库只存相对路径 + MD5 + 大小。
- 文件通过后端接口流式下载（鉴权 + 可选水印），不暴露真实磁盘路径与目录列表。
- 容量预留：建议数据盘 ≥ 200GB，附件目录挂载独立分区，便于扩容与备份。
- 存储层做接口抽象，后续可换 MinIO。

| 类别 | 要求 |
| --- | --- |
| 性能 | 列表查询 ≤ 1s（万级数据），单文件上传支持 500MB 以上；单人使用，无需并发优化 |

| 备份 | 数据库每日全备；附件每周全备；主密钥离线单独保管；提供恢复演练步骤 |

| 可维护 | 配置外置（数据库地址、主密钥路径走 application.yml + 环境变量）；logback 日志滚动；SpringDoc OpenAPI 接口文档 |

## 七、技术方案（已确认）

### 7.1 技术选型

| 层次 | 选型 | 说明 |
| --- | --- | --- |
| 后端 | Java 17 + Spring Boot 3.2.x + Spring Security | 用 Docker 部署后不受 CentOS 7 glibc 限制；若你更习惯 JDK 8，可退回 Spring Boot 2.7.x，业务代码基本一致 |
| 持久层 | MyBatis-Plus 3.5.x + HikariCP | 单表 CRUD 用 MP，复杂查询写 XML |
| 数据库 | MySQL 8.0（容器） | utf8mb4 / InnoDB，单机小体量足够 |
| 认证 | JWT 无状态 Token + 登录失败锁定 | 个人使用无需 Redis，Token 黑名单用本地缓存（Caffeine） |
| 加密 | JDK 原生 AES-256-GCM，主密钥文件挂载 | 主密钥不进代码、不进数据库、不进镜像 |
| 前端 | Vue 3 + Vite + Element Plus + Pinia + Axios | 构建产物放进后端 jar 的 static 目录，单体部署只暴露一个端口 |
| 文件存储 | 宿主机目录挂载（本地磁盘） | 存储层做接口抽象，后续可换 MinIO |
| 部署 | Docker Compose：mysql + app（nginx 可选） | 宿主机 CentOS 7.9 |
| 文档 | SpringDoc OpenAPI（Swagger UI） | 开发期自带接口文档 |

### 7.2 部署架构

    浏览器 --HTTPS/HTTP--> [app 容器 :8080]  Spring Boot 内嵌 Tomcat + Vue 静态资源
                                  |
                                  +--> [mysql 容器 :3306，仅绑定 127.0.0.1]
                                  +--> 挂载 /data/pdm/uploads   附件
                                  +--> 挂载 /data/pdm/keys      主密钥 master.key
                                  +--> 挂载 /data/pdm/logs      应用日志
    宿主机 cron：mysqldump 每日备份 + uploads 每周备份

需要 HTTPS 时再加一个 nginx 容器做 TLS 终结并反代到 app:8080；纯内网个人使用也可先只跑 HTTP + 防火墙限制来源网段。

### 7.3 宿主机目录规划

| 路径 | 用途 | 权限 |
| --- | --- | --- |
| /data/pdm/mysql | MySQL 数据目录 | 容器内 mysql 用户 |
| /data/pdm/uploads | 交付文档与凭据附件 | 700 |
| /data/pdm/keys/master.key | 凭据加密主密钥 | 600，离线另存一份 |
| /data/pdm/logs | 应用日志 | 755 |
| /data/pdm/backup | 数据库与附件备份产物 | 700 |
| /opt/pdm | 镜像构建上下文、compose 文件、脚本 | 755 |

### 7.4 CentOS 7.9 装 Docker 的注意点

- 系统已 EOL，`yum` 的 base/updates/extras 源要改指向 `vault.centos.org`，否则装不上依赖。
- 内核 3.10 使用 overlay2 需要 XFS 支持 d_type，先执行 `xfs_info /var/lib/docker | grep ftype`，必须为 `ftype=1`（CentOS 7 默认满足）。
- 建议装 `docker-ce` + `docker-compose-plugin`（用 `docker compose` 子命令，别用已停维护的 python2 版 docker-compose 1.x）。
- 内网无外网时：在有网机器上 `docker save` 出镜像 tar，拷贝到虚拟机 `docker load` 导入。
- 时间同步务必开启（chronyd），否则 JWT 过期判断与证书校验会出错。

### 7.5 备份与恢复

- 每日 02:00 cron：`mysqldump --single-transaction` 导出到 /data/pdm/backup，保留 14 天。
- 每周日：打包 uploads 目录，保留 8 份。
- 主密钥 master.key 单独备份到与服务器不同的位置（U 盘 / 密码管理器），**数据库备份和主密钥绝不能放在一起**，否则等于明文泄露。
- 恢复演练：新建容器 → 导入 SQL → 挂回 uploads 与 master.key → 校验凭据可解密。
